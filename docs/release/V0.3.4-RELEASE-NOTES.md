# BitChat RustPy `v0.3.4` — Phase 3 Production Release Notes

**Release Date:** 2026-11-19  
**Tag:** `v0.3.4`  
**Milestone:** Phase 3 — Native Rust BLE Transport, Noise XX over BLE, Reference `bitchat-tui` Interoperability, Live Bluetooth Diagnostics & Mouse Navigation Stability

---

## Highlights

BitChat `v0.3.4` delivers the **Phase 3** engineering milestone across Windows, Linux, and macOS:

1. **Modular Native Rust BLE Transport Architecture (`rust/bitchat-core/src/ble/`):**
   - Replaced the single-file BLE helper stub with a real modular Rust BLE transport stack (`types.rs`, `advertisement.rs`, `connection.rs`, `manager.rs`, `windows_winrt.rs`, `linux_bluez.rs`, `macos_corebt.rs`) executing platform OS BLE operations off Python's GIL (`py.allow_threads`).
   - Native Windows WinRT BLE backend (`windows` 0.58), native Linux BlueZ D-Bus backend (`zbus` 5), and truthful macOS CoreBluetooth capability probing.
2. **Windows GATT Server + Decoupled Companion Advertisement Lifecycle:**
   - Fixed the critical coupling bug in `src/bitchat/ble/server.py` and `rust/bitchat-core/src/ble/windows_winrt.rs` where a companion manufacturer `BluetoothLEAdvertisementPublisher` failure tore down an already-working `GattServiceProvider` and `GattLocalCharacteristic`.
   - Independent status tracking for `gatt_server_status` vs `discovery_advertisement_status` with honest status 3 (`Aborted`) reporting.
3. **Reference `bitchat-tui` (`107a13c`) Noise XX & Binary DM Interoperability:**
   - Added native Rust `decode_chat_payload_raw` and `encode_bitchat_message_payload_raw` supporting plain UTF-8, `[0x04] || UTF-8`, `[0x04] || binary BitchatMessage`, bare binary `BitchatMessage`, and nested `BitchatPacket(Message)` payloads while preserving strict fail-closed Noise XX authentication and nonce-0 replay rejection.
4. **Live Bluetooth Settings Diagnostics (`src/bitchat/tui/screens/settings.py`):**
   - Replaced the wrong hardcoded `0000fee0-0000-1000-8000-00805f9b34fb` UUID and falsely hardcoded `"Active / Scanning"` status with live asynchronous hardware & transport telemetry, canonical BitChat Service/Characteristic UUIDs, zero blank diagnostic boxes, and an explicit **Refresh Bluetooth Information** action.
5. **Mouse Navigation Jitter & Screen Fluctuation Eliminated (`status_bar.py`, `app.py`, `screens/*.py`):**
   - Fixed `StatusBar.on_button_pressed` triple-firing every action click (`ActionTriggered` + direct `app.action_*` call + bubbled `Button.Pressed`), added `event.stop()` across all screen button handlers, batched multi-layer screen pops (`batch_update()`), and deduplicated `PeersScreen` DataTable rebuilds.
6. **Strict Scanner Peer-ID & GATT Property Validation:**
   - Enforced full 8-byte (16-hex-char) non-zero, non-broadcast peer IDs for BLE service data and strict `notify` + `write`/`write-without-response` GATT characteristic validation.
7. **Homepage Preservation:**
   - Both `src/bitchat/tui/screens/home.py` and `website/index.html` were preserved completely untouched.
